How do I generate a random password?

A secure random password is the strongest thing you can put in a password field. The generator on the PassMeter checker uses your browser's cryptographic random number generator, not Math.random.

Quick answer: Open the PassMeter checker, click Generate strong password, and a 16-character password built from letters, digits and symbols is created locally using crypto.getRandomValues. Nothing is transmitted or stored.

  • Is Math.random safe for generating passwords? — No. Math.random is not cryptographically secure and its output can be predicted. Use crypto.getRandomValues instead.
  • Should I use the same generated password everywhere? — Never. Reuse means one breached site exposes every other account. Generate a unique password per site and store them in a manager.

Is a random password really stronger than a complex one?

Yes, and the gap is large. A 16-character random string from a 94-character alphabet carries about 105 bits of entropy. A human-invented complex password of the same length usually carries 35 to 50 bits because it follows human patterns.

What characters should a generated password contain?

Aim for at least 16 characters drawn from the full 94-character printable set: uppercase, lowercase, digits and symbols. Some services reject certain symbols; if a generated password is rejected, request one without them rather than weakening a long password into a short one.

How should I store a generated password?

Immediately in a password manager. A generated password you cannot recall is only safe if it lives in exactly one encrypted vault. Never paste it into a chat message, a spreadsheet, or a notes file.

Do I need a different generated password for every site?

Yes. Generate a unique 16-character password for every account, then let the manager fill it in. Reuse is the single biggest practical risk even when each individual password is strong.
