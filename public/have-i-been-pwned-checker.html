Has my password been leaked in a breach?

The PassMeter breach check sends only a five-character prefix of a SHA-1 hash of your password, so no server ever learns the password itself. Results show how many times it appears in known leaks.

Quick answer: If a password appears in any breach list, treat it as compromised. Change it everywhere you used it, enable 2FA, and never reuse it again. The check is anonymous by design: only a hash prefix leaves your browser.

How does the k-anonymity breach check work?

Your browser hashes the password with SHA-1, splits the hash into a five-character prefix and the rest, and sends only the prefix to the range API. The server returns every hash suffix that starts with that prefix. Your browser compares the suffixes locally. The server sees a prefix shared by roughly 800,000 other hashes, so it learns nothing about you.

What should I do if my password shows up as breached?

  1. Change it on the affected service right away, and on every other service that reused it.
  2. Enable two-factor authentication, ideally with an authenticator app rather than SMS.
  3. Check for signs of misuse: unexpected logins, changed recovery email, new forwarding rules.
  4. Revoke active sessions on the compromised account if the service offers it.

Why are breach lists full of old passwords?

Credential stuffing: attackers take leaked username and password pairs and replay them against thousands of other services automatically. A password that leaked in 2013 and was reused in 2024 is effectively re-leaked every time a new service breaches. Uniqueness is the defence.

Does checking a password in a browser risk anything?

Only if the tool is dishonest. A correct implementation sends a hash prefix, not a password. Verify in your browser's network tab that no request contains the raw password, and that the request goes to the documented range endpoint.

Should I check my work password for breaches?

Generally no. Employer credentials are governed by internal policy, and checking them against public breach lists may violate acceptable-use rules. Check personal passwords, and ask your security team to run sanctioned internal checks instead.
